План автоматизации тестирования

Перечень автоматизируемых сценариев:
1. Позитивные тесты
   - Покупка тура обычным платежом с успешной оплатой.
   Тестовые данные: Валидная карта с номером 4444 4444 4444 4441. Остальные данные валидные.Шаги: Заполнить форму заказа тура, ввести реквизиты карты, подтвердить оплату.Ожидаемый результат: Появляется сообщение «Операция одобрена банком», статус транзакции «APPROVED». Соответствующая запись создается в базе данных с указанным статусом.
   - Покупка тура кредитным платежом с успешным одобрением кредита.
   Тестовые данные: Корректная заявка на кредит, доход клиента достаточный, положительная кредитная история.Шаги: Подать заявку на покупку тура в кредит, заполнить анкету заемщика, отправить заявку.Ожидаемый результат: Сообщение «Кредит одобрен», соответствующая запись с состоянием «CREDIT_APPROVED».
2. Негативные тесты
   - Попытка оплаты несуществующей картой.
   Тестовые данные: Карта с номером 4444 4444 4444 4442 (несуществующая). Шаги: Попробовать оплатить тур введением вышеуказанных данных.Ожидаемый результат: статус транзакции "DECLINED", возникает ошибка с текстом «Ошибка! Банк отказал в проведении операции».
   - Ошибка сервера базы данных.
   Тестовые данные: Пользователь пытается купить тур, сервер БД временно недоступен.Шаги: Отправить запрос на покупку тура при отсутствии связи с базой данных.Ожидаемый результат: Отображается сообщение типа «Сервер временно недоступен, попробуйте позже».
   - Сервер платежа временно недоступен.
   Тестовые данные: Доступность платежных сервисов нарушена.Шаги: Осуществить попытку покупки тура при недоступности внешнего шлюза платежей.Ожидаемый результат: Видимое уведомление вроде «Система оплаты временно отключена, обратитесь позднее».
   - Оплата недействительной картой.Тестовые данные: Валидная карта с номером 4444 4444 4444 4441, срок действия истекший («01/20»), CVV правильный (999).Шаги: Ввести указанные данные и попытаться завершить оплату.Ожидаемый результат: Получено сообщение «Ошибка: данная карта больше не действительна».
   - Использование неверных реквизитов карты (неправильный CVV).Тестовые данные: Верный номер карты (4444 4444 4444 4441), срок действия «08/26», неправильный CVV (000).Шаги: Использовать указанную карту для оплаты.Ожидаемый результат: Поступило сообщение «CVV код неверен».


Перечень используемых инструментов с обоснованием выбора:
1. Python — высокоуровневый язык программирования, простой и понятный синтаксис, подходит для быстрого написания тестов.
2. Requests — библиотека Python для отправки HTTP-запросов, удобная для взаимодействия с RESTful API.
3. PyTest — фреймворк для модульного и интеграционного тестирования, позволяет писать читабельные и гибкие тесты.
4. Selenium — инструмент для автоматизации браузера, используется для UI-тестирования веб-приложения.
5. Allure — система отчетности, помогает визуализировать результаты тестирования.
6. GitHub Actions — CI/CD решение для автоматического запуска тестов при каждом коммите изменений.


Перечень и описание возможных рисков при автоматизации:
1. Ошибка в конфигурации баз данных: Если неправильно настроены учетные записи и URL базы данных, приложение не сможет подключиться к ней.
2. Отказ службы платежей: Платежный шлюз может отказать в обслуживании, нарушая процесс прохождения теста.
3. Проблемы с эмулятором: Возможны проблемы с настройкой и работой эмулятора Payments Gateway и Credit Gate.
4. Неправильная обработка исключительных ситуаций: Возможно отсутствие обработки ошибок в коде приложения, приводящее к некорректному поведению в негативных сценариях.


План сдачи работ:

- Через три дня: отправка плана автоматизации.
- Первая неделя: первые прогонки базовых тестов.
- Вторая неделя: полный набор тестов, интеграция Allure и GitHub Actions.
- Третья неделя: финальная проверка всех тестов и подготовка отчета.
